Your task is to design and implement the feature from issue #15; read it.

Apart from the issue specification I would like to propose the JSON format. You can find a sample in `issues/015-file-persistence/format-sample.musp.json`. It should be self explaining and the comments provide clarification. Extra clarifications:
- `scaleEditor.intervals` is interpreted differently based on `scaleEditor.mode`, it contains either absolute or relative intervals. If it's `relativeIntervals`, then it's cardinality is 1 item smaller than the number of notes (number of `scaleEditor.noteProperties`), but it has the same size as `scaleEditor.intervalProperties`. If `scaleEditor.mode` is `absoluteIntervals`, than its cardinality is the same as the number of notes, but greater with 1 item than `scaleEditor.intervalProperties`. Note that `scaleEditor.intervalProperties` always refers to intervals between successive notes. `settings.intervalType` influences `scaleEditor.intervals` item type as explained in the comment.
- Settings allows setting Notation mode. Currently switching Notation hides some Scale Editor features, but their values are not lost. Similarly, saving will persist those hidden values too. Opening will restore them. In the file format, `scaleEditor.noteProperties` is an array of objects. Each object has a property for each Notation mode, with an object containing notation-specific properties. So the state of each notation mode is persisted regardless of what `settings.notation` is set to, similar with the UI. Only set a notation-specific property if its value is different from the default 1. `"byzantine": {}` means that for that note, none of the note properties in Byzantine Notation mode are set. `byzantine` can also be omitted with the same effect in the JSON file. Or those JSON properties could be set explicitly to those default values.
