SMuFL accidentals in Bravura Text

Working page for issue #13. It reconstructs Figure 2 of the Sagittal paper — the 72-EDO ladder — from real font glyphs, shows what has to be composed by hand and what does not, and lays out the candidate groups for the accidental picker. Every symbol on this page is live text in fonts/BravuraText.woff2, not an image: select it and copy it.

1 · The 72-EDO ladder — Figure 2 reconstructed

Twelve steps to the whole tone, so one step is a twelfth of a tone (16.67 ¢) and the apotome is six of them. The Revo row is what SMuFL ships precomposed: one codepoint per degree, a sagittal arrow whose shaft count carries the apotome. The Evo (mixed) row is the one drawn in Figure 2 of the paper, and it is not in SMuFL as single glyphs — the four outer degrees are a sagittal glyph followed by an ordinary  or , two codepoints in a row.

Degrees ±1, ±2 and ±3 are identical in both flavours — they are the single-shaft symbols, which is exactly the point the paper makes about the two flavours coexisting. Only ±4, ±5 and ±6 differ.

2 · Composing an Evo pair: the spacing question

Every glyph in the font has zero side bearings: the advance width is exactly the width of the ink. Two accidentals in a row therefore touch, with not one pixel between them. That is deliberate — a notation engine positions accidentals itself — but it means a plain two-character string is too tight. Bravura Text provides three blank advance glyphs to open the gap, measured in staff spaces:

U+0020 = ½ staff space, - = 1 staff space, = = 2 staff spaces. They carry no outline at all, so they are safe inside a fillText() string as well as in the DOM. In the DOM the containing element needs white-space: pre or the leading space is collapsed away. Bravura (the notation face) has only U+0020, and there it is 0.4 of a staff space rather than a half — one more reason §6 lands on Bravura Text.

3 · How SMuFL glyphs compose — a primer

Four mechanisms, from the one you will use constantly to the one you almost certainly will not. Only the first two matter for issue #13.

3a · Plain concatenation (what an Evo pair is)

A string of two codepoints. The shaping engine lays glyph two immediately after glyph one at its advance width. Nothing clever happens, and because of the zero side bearings nothing needs to: U+E305 U+E262 already reads as one compound accidental. Add a spacer character if you want air. This works identically in the DOM and in ctx.fillText().

two codepoints, no markup:  U+E305 U+E262

3b · GPOS kern — pair positioning

A GPOS (Glyph POSitioning) table stores adjustments applied after the glyphs are chosen: nudge this glyph left by 40 units when it follows that one. Bravura Text carries one GPOS feature, kern, with 1 333 pairs — almost all of them for figured-bass digits and chord-symbol parts. None of the accidental pairs used on this page is kerned, so what you see is pure advance-width stacking. It is still worth knowing the feature is on by default in every browser, and that font-kerning: none turns it off if a future pair surprises you.

3c · GSUB liga — substituting a sequence for one glyph

A GSUB (Glyph SUBstitution) table replaces a run of glyphs with a different glyph. Bravura Text uses this for vertical positioning: 16 codepoints, U+EB90…U+EB9F, each meaning “raise/lower the next symbol by n staff positions”. Type the shifter, then the symbol, and the ligature lookup swaps the two-glyph run for a single pre-shifted glyph. That is where Bravura Text’s 19 269 glyphs come from, against Bravura’s 3 715 — the same 3 468 symbols, plus every vertical variant.

a sharp, unshifted → raised 2 → lowered 3: -- U+E262 · U+EB91 U+E262 · U+EB9A U+E262

If those three sharps are at three different heights, your renderer applied the ligature. Canvas fillText() applies it too — browsers shape canvas text through the same engine as DOM text. Issue #13 draws accidentals free-standing beside a chart, not on a staff, so this is background knowledge rather than a tool we need.

3d · Zero-width glyphs — overprinting

Staff glyphs (U+E010…U+E014) and leger lines have an advance width of zero, so whatever follows is drawn on top of them rather than after them. That is the SMuFL way of putting a symbol on a staff without positioning code: emit the staff, then the symbol.

5-line staff, then three accidentals: --

Three staff glyphs at zero advance stack in the same place and only widen the drawing, not the cursor; the accidentals that follow start at x = 0 of the run and land on the middle line, which is where every movable glyph sits by default.

6 · Why Bravura Text and not Bravura

Both faces carry the identical 3 468 SMuFL symbols at the same codepoints, so this is a question about metrics, not repertoire. The measurements below are read live from the browser with ctx.measureText() at 100 px, so the numbers are the ones the app would actually get.

Bravura itself is deliberately not vendored: only Bravura Text is. The Bravura rows above are therefore read from a locally installed copy if you have one — the figures to expect are 0.249em advance and a 4.020em line box for the sharp. On this machine Bravura is not installed, so those rows fell back to a system font and mean nothing; install it, or drop Bravura.woff2 beside BravuraText.woff2 and add an @font-face, to see the real comparison.
